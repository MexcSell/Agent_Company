# Threat model

SPEC-14 S14-R-09 (`ASEAO_SPEC-14_Enterprise_Security_Governance.pdf` §19): STRIDE plus the AI-specific
threats, each mapped to the control in this repository and the test that holds it. Written against the code of
2026-11-05.

**Review this file** when a new executor, model provider, integration (MCP server, A2A, webhook) or network
path (a listener, a crawler target, an outbound call) is added, and add its row and test in the same change.

## Scope and assumptions

- One host, one process (`supervise` → the API on 127.0.0.1:4910, nginx on 4900). SQLite, one writer.
- Actors: administrators and members (people, `auth.py`); agents (`registry.py`), which run only through
  executors (`executors.py`); A2A clients an administrator issued (`a2a.py`); the public web (crawler).
- Agents have no credentials of their own: model keys stay in the server environment and the DB settings;
  pushing uses each user's own GitHub token or key (`gitsync.py`) and happens only on `/sync` or `AUTO_PUSH`.
- **Outside this model, by decision of the owner** (CLAUDE.md): the Workspace terminal and Claude Code panel,
  `containers.py` and `machines.py` are the administrator's own host-wide tools, not agents. They are admin-only,
  audited, and their WebSockets check the Origin; nothing here constrains what an administrator runs with them.
- Not defended: a malicious administrator, a compromised host or Python environment, a compromised model provider
  that returns valid-looking but wrong code that passes every check (the human merge approval is the last line).

## Trust boundaries

| Boundary | What crosses it | Control at the boundary |
| --- | --- | --- |
| Browser → API | requests with a session cookie | device sign-in, sealed cookie (`api.py`, `transport.py`), permissions (`auth.py`), first admin only from localhost |
| A2A client → API | JSON-RPC with a bearer token | `a2a.authenticate` (only the token's SHA-256 is stored); tasks become `origin="a2a"` goals that always wait for approval |
| Web → knowledge | crawled pages and RSS/Atom feeds (G-R-10); the URLs of research requests, fetched again on each run of a recurring one (`research.ReportThread`) | `research._is_public_host` (no private addresses, also after redirects), robots, `injection_flags`, `classify_source`; a feed is parsed only without a DOCTYPE (no entity expansion: `test_research.py::test_a_feed_with_a_doctype_is_refused`), its entries are stored, never fetched, and pass the same flags; a PDF (up to 25 MB) is parsed only in the L3 sandbox by `pdftext.py` (no network, memory/task/CPU limits, 60 s, a scratch directory; not parsed when the sandbox is unavailable unless an administrator set it `off`: `test_research.py::test_a_pdf_is_not_parsed_when_the_sandbox_is_unavailable`), and its text passes the same flags; a recurring request stops when its budget is used, waits under an E3/E4/E5 stop, and an overlapping request is answered by the existing one instead of fetching again; a report reaches knowledge, the search and its goal only after its review (S06-R-04): every claim must quote or match a stored document (`research.check_claims`), a second agent (another model family when one is usable, else a person) agrees per claim, unbacked claims are dropped, the reviewer's prompt wraps the report as untrusted data, and PROPOSAL lines become ordinary pending proposals (restricted ones need a person) |
| Eval suite → research prompt | the research benchmark's reference documents (`evals/research.json`, G-R-13), some planted as unreliable or with injected instructions, put in front of the research room by `research_eval.run` | they reach only that eval run's report prompt, wrapped as `<document>` data like crawled pages; they stay in memory (ADR 0003: unsaved documents passed to `research.check_claims(documents=…)`) and are never stored: no Document, report record, knowledge item, blackboard entry or proposal, and an eval report is never reviewed, approved or transferred, so they cannot reach `research.search`, retrieval or another prompt; a report that repeats an injected claim fails the run (`forbidden_found`, compliance) | `test_research_eval.py::test_reference_documents_stay_out_of_search_knowledge_and_the_blackboard`, `test_research_eval.py::test_an_injected_claim_fails_on_forbidden_found` |
| Model → worktree | model output, CLI tool calls | the tool gateway (`executors.gate`), `worktrees.ensure_sandboxed`, `write_files`, `governance.check_command`, the quality gate |
| Project docs → planner prompt | `docs/requirements/*.md` of a project's checkout, imported as requirements (`requirements.import_docs`), whose texts reach the planner (`requirements.planner_note`) | import only by an administrator and only from `<project>/docs/requirements` (no free path); a merged change of those files reaches requirements only by a new import; only the goal's own and at most eight related requirements, each capped; requirement texts are context like blackboard entries and pass the same gateway and gate; new versions go back to draft for a person |
| Repository standards and research documents → task prompt | the first of `CLAUDE.md`, `AGENTS.md`, `CONTRIBUTING.md`, `README.md` of the project (`learning.project_standards`) and the best matching collected documents (`learning.task_references`, S11-R-03) | standards are read from the goal's base branch in the project's own checkout (`git show <base>:<file>`), never the worktree (also for a detached HEAD), so an agent's edit of `CLAUDE.md` in a goal cannot reach the other agents' prompts; a file that `research.injection_flags` flags is left out and logged; capped at 3000 characters; at most three documents, flagged pages never, 300-character excerpts; research reports of another project classified above internal are left out (`research.search(goal_id=)`, also for the research step); the study rotation, whose definition files serve every project, takes only public/internal lessons and reports (`search(shared_only=True)`); both wrapped as data, not instructions |
| Templates and team notes → planner prompt | workflow template texts (`strategies.planner_note`: name, description, instructions) and the reasons of a goal's team changes (`teams.planner_note`), which the planner's own `team` field or an administrator wrote | templates are saved only by an administrator (`POST /api/strategies/{kind}`, audited, validated fields, each text capped at 2000 characters, old versions kept); team reasons capped at 500 characters, at most 5 additions and 10 releases per plan, the General Manager cannot be released; a template only restricts a plan (roles, writes) and may drop the quality commands only when its tasks change no files (`strategies.validate`); the plan still passes the gateway and the gate |
| Goal outcomes → workflow templates | live goals' outcomes and events (`orchestration.evaluate`), which agents influence by their work, become recommended template changes; an eval suite measures them (S04-R-13) | the rules are deterministic and only tighten or add iterations; a candidate that turns on writes or recruitment, drops checks, the review or protected tests, widens paths or opens the roles is recorded rejected (`orchestration.violations`, §20.3); a recommendation never changes a template: only an administrator applies one (`experiments.apply`, API admin-only, audited `high`), and only against the version it was measured on; the canary restores the previous version when live goals get worse; `tests/test_strategy_evolution.py` |
| Task output → project plan | `BLOCKER:` lines of a task's output (`contracts.blockers`), shown to every user of the project as blockers in the Plan tab, `/status` and the stand-up | at most three per task, each capped at 256 characters; stored as data in the task's gate and opened by `management.sync` under the cause `task:<id>:blocker:<n>`, so they close themselves when the goal ends or re-plans and never change a goal's state; rendered escaped (`esc()` in projects.js); they reach no planner prompt or command |
| Failure evidence → analysis → knowledge and proposals | the root-cause analysis (`rca.py`, S07-R-02): defect details, failed conditions, run errors and event messages of failed goals reach the General Manager's prompt; its answer becomes an `operational` knowledge item (retrieved into later prompts) and up to three proposals | the evidence pack is collected by the platform, each line capped (150-300 characters), and passes to the model like gate feedback does; the answer is parsed, not executed: a cause counts as confirmed only when it cites the pack's own references; the item is screened by `learning.screen` like every lesson, and a screened-out analysis creates no proposal; the analysis of a secret goal is withheld like its lessons (S14-R-05) and proposes nothing; proposals stay pending (agents never approve restricted ones, `projects.RESTRICTED`) and a spawned goal passes the gateway, the gate and the merge approval |
| Agent-written code → host | quality commands, task acceptance commands and milestone checks (`contracts.run_command`), code-improvement benchmarks (`selfevolve.run_benchmark`): they execute what the agents wrote | the L3 sandbox (`sandbox.py`, S14-R-07): bubblewrap with no network, own PID/IPC/UTS namespaces, every capability dropped, only system directories and toolchains read-only and the work directory writable (its `.git` and git directories read-only, so no planted hook or rewritten `gitdir:` pointer), `data/`, `.env`, `~/.claude`, `~/.codex`, `~/.ssh` hidden even below a bound directory, HOME of its own (`data/sandbox/home`), memory/task/CPU limits through a systemd scope; the environment is allow-listed on the host as well (no keys, tokens, secrets). Mode `sandbox`: `auto` falls back to the host and marks the check `L2` with the reason, `required` refuses to run; a project may only tighten it; A2A goals always require it. The one networked step is the prepare (`uv sync --frozen`, `npm ci --ignore-scripts` for a changed lock file, inside the same filesystem sandbox) |
| Gate → advisory databases | the dependency audit (`dependencies.audit`, S08-R-05): `pip-audit` (PyPI/OSV) and `npm audit` (npm registry) send the names and versions of the audited lock or requirements file | only when a manifest changed and the tool is installed; the platform's own fixed argument lists (manifest paths from the diff never pass a shell); `--no-deps --disable-pip` and `uv export --frozen` offline, `npm audit --package-lock-only`: nothing is installed or built, no agent-written code runs; in the L3 sandbox with network, the worktree read-only, the filtered environment; manifests are read from git objects and a symlinked one is never followed; setting `dependency_audit` off stops it |
| Worktree → project checkout | merge | independent review, `loop.approve` (a person: an administrator or a user with a delegation of `approve_goals` for that project, `policies.allows`), `checks.*` at the gate |
| Server → model provider | prompts | classification clearance per model (`router.cleared`, `learning.goal_level`) |
| Server → another Claude subscription | a `claude_code` model with its own `account`: its runs use the Claude Code sign-in in `data/claude-accounts/<account>/` (`CLAUDE_CONFIG_DIR`, `executors.claude_env`), where the CLI also refreshes the token | the account is a folder name (`router.claude_config_dir`: no `/`, no `..`), set only by an administrator (`manage_models`); the folder is 0700 and `.credentials.json` 0600; `data/` is hidden from the L3 sandbox; the same trust as the host's own login (`~/.claude`) — the agent CLI runs at L2 (Known gaps) | `test_execution.py::test_claude_code_model_with_its_own_account` |
| Workspace / GM panel → a Models-page model | the administrator picks a `claude_code`/`codex` model by name in the panel's model menu: it runs with that model's id, sign-in and base URL (`workspace.router_models`, `executors.claude_env`); a conversation that moves to another sign-in has its transcript copied into that `CLAUDE_CONFIG_DIR` and back afterwards | admin-only and audited (`workspace_claude` records the model); only an enabled model of the conversation's own agent, looked up by name (no free-form address or folder from the browser); the same accounts and addresses the agents already use | `test_workspace.py::test_claude_panel_runs_a_models_page_model_with_its_own_sign_in` |
| Server → GitHub | pushes | only `/sync` or `AUTO_PUSH`, with the ordering user's own credentials |

## Threats, controls and tests

| Threat | Example here | Controls | Tests |
| --- | --- | --- | --- |
| **Spoofing** | someone else's browser uses the API; a forged A2A client | device secrets, sealed cookie bound to the browser (and IP over HTTP), admin registration from localhost only, signup rate limit (`api._signups`); A2A bearer tokens issued by an administrator | `test_api.py`, `test_transport.py`, `test_a2a.py::test_authentication_version_and_unsupported_methods` |
| **Tampering** | an agent edits files outside its goal, the audit log, or the platform's control plane | `worktrees.ensure_sandboxed`, `write_files` refuses `..` and absolute paths (incident SEV-2, rule `path_escape`); hash-chained audit (`governance.audit`, `verify_audit`); `selfevolve.protected_paths`; change boundaries (`checks.boundary_violations`, `--permit`) and scope (`checks.scope_violations`) | `test_threats.py::test_a_compromised_model_cannot_write_outside_the_worktree`, `test_loop.py`, `test_governance.py::test_audit_chain_detects_tampering`, `test_selfevolve.py`, `test_safety.py` |
| **Repudiation** | "which agent did this?" | every run records agent, model, executor, goal/task, isolation, tools, permissions used, what was withheld and each tool call a CLI run made (tool, short input with credential-like text redacted, failed or not; `Run.tool_calls` from Claude Code's stream-json and Codex's `--json` events, at most 200) (`Run`, `usage.record`); goal trace (`loop.trace`); audit of administrative actions (`api._audit`); workflow transitions with actor | `test_gateway.py::test_runs_record_the_grant_and_the_loop_audits_what_was_withheld`, `test_gateway.py::test_claude_code_runs_record_every_tool_call_redacted_and_in_the_trace`, `test_orchestration.py`, `test_workflow.py` |
| **Information disclosure** | a confidential project's lessons or a secret order reach a hosted model or another project | classification on projects, orders, uploads, lessons (`router.cleared`, `NotCleared`); secret work stores no lesson text; cross-project retrieval only of public/internal items (`learning._scope_ok`); credentials in a change stop the goal (`checks.scan_secrets`, SEV-2) | `test_threats.py::test_one_projects_work_never_reaches_another_projects_prompts`, `test_classification.py`, `test_knowledge.py::test_a_confidential_lesson_of_project_a_never_reaches_project_b`, `test_knowledge.py::test_a_tasks_package_lists_matching_research_documents_but_not_another_projects_confidential_report`, `test_safety.py::test_a_secret_in_the_change_stops_the_goal_and_opens_an_incident` |
| **Denial of service** | a runaway CLI, an endless loop of iterations, cost blow-up | per-run timeout capped by the tool contract, process groups killed on timeout/stop, 5 M character output cap; goal cost/token/time budgets that pause, agents at once per goal, child goals capped by the parent's remainder (no budget left: no child goal), cost > 2× estimate pauses; per-agent concurrency and daily quotas; daily room budgets over a room and its sub-rooms; `MAX_ITERATIONS`; emergency stop E0–E5 that needs no model | `test_safety.py` (E5 kills a running executor within 5 s), `test_failure_modes.py`, `test_registry.py`, `test_budgets.py` (`test_a_rooms_daily_budget_covers_its_sub_rooms_and_pauses_the_goals_that_need_them`) |
| **Elevation of privilege** | an agent gets Bash, write access, MCP tools or a higher autonomy level | the tool gateway: `write` + G2 for changes, `shell` for commands, G3 for MCP, G0 runs nothing (S14-R-02, S14-R-06); only administrators change an agent's permissions or autonomy (also by rollback); recruits get no more than their role template, a new role no `shell`/`network` until an administrator grants it, and only administrators approve recruitments (refusals audited); G5 is reserved to humans; agents never approve a restricted proposal (`projects.RESTRICTED` names permissions, autonomy, tools, shell, sandbox, network/write access, MCP, deployment, …); a gated room's agents are enabled (or resumed) only through its measured room gate or an audited override, and a room trial staffs them for its own eval goals only, their clones disabled (G-R-04) | `test_gateway.py`, `test_threats.py::test_a_compromised_model_cannot_widen_authority_through_a_proposal`, `test_workflow.py`, `test_recruitment.py::test_only_administrators_decide_and_a_refused_attempt_is_audited`, `test_room_gate.py` |
| **Delegated authority** | a delegate merges into a project they were not given, after the grant expired or was revoked; an agent made an approver of its own work; a project rule loosens a company one | `policies.allows` checks scope, expiry and revocation on every call (no cached right); grantees are users only (agents have no user row), never the platform project, at most `MAX_DAYS`; grant, revoke and each delegated approval are audited (`severity=high`); a project's rules can only tighten (`policies._check_project_rules`, `effective` takes the stricter of both at use); governance settings keep versions with author (`policy_versions`) | `test_policies.py::test_a_delegate_approves_only_the_delegated_project_while_the_grant_holds`, `test_an_expired_delegation_grants_nothing`, `test_what_cannot_be_delegated`, `test_a_project_lowers_the_goal_budget_but_cannot_raise_it_above_the_company_limit` |

## Known gaps

- **Agent CLI runs stay L2** (S14-R-07): checks and benchmarks run in the L3 sandbox, but Claude Code and Codex
  themselves run as the server user in the worktree (they need the network and their logins), and Claude Code's
  `CLAUDE_BASH` tools (`pytest`, `uv run`, `npm run`) execute agent-written code there. A model that escapes those
  tool restrictions, or a test it runs through them, could read the host as that user. Run the service in a
  disposable VM or container without production credentials for untrusted goals.
- **The prepare step has network**: a changed lock file is installed (`uv sync --frozen`, `npm ci --ignore-scripts`)
  with network inside the filesystem sandbox, so a malicious build backend of a new dependency could send the
  worktree's code out. Dependency manifests are a change boundary (`--permit dependencies`) and the gate fails the
  change, but the prepare runs before the gate decides.
- **Codex read-only runs** may still execute read-only commands inside Codex's sandbox, also for an agent without
  `shell`.
- Workload identity, ABAC, HSM/vault and field-level encryption are skipped (single host, SPEC-14 "Skipped").
