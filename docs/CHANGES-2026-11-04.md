## General Manager = Claude Code (docs/1.claude-code-multi-agent.jpg)

- **The GM's route is "Claude Code"** (existing database migrated once). `enable_claude_code` was **switched
  on** (Settings, DB override of `.env`), because without it the GM ran on the offline simulator: there is no
  `ANTHROPIC_API_KEY` in `.env`. This also turns Claude Code on for the developer, frontend, devops and
  tech_scout routes, so goals now use the server's Claude subscription. Turn it off in Settings if unwanted.
- **Changing the GM later**: Agents → Company General Manager → Model. Choices: any catalog model; another
  agent (`agent:<id>`: the GM then uses that agent's model or its role's route); or a Claude Code at another
  address (Models → Add model, kind Claude Code CLI, with a base URL: passed as `ANTHROPIC_BASE_URL`).
- **What the GM does with an order**: on the Projects page an administrator talks to the GM as a Claude Code
  conversation in the project folder. Its instructions (`gm.py`) give it a toolbox
  (`python -m agent_company gm status|agents|create-agent|set-model|catalog|add|mcp|configure|goal|study`):
  staff or create agents, add missing skills/plugins/rules/commands to the catalog, write the project's
  `.claude/` configuration, and start the goal loop. Goals it queues are picked up by the server.
- **The goal loop** (Plan → Build → Review → Fix): on iteration 1 a CLI GM (Claude Code / Codex) first updates
  the project's `.claude/` (agents, rules, skills, commands, settings.json, .mcp.json) **in the goal's
  worktree**; anything it changes outside `.claude/` and `.mcp.json` is put back. Every goal writes
  `.claude/specs/<slug>/` (requirements, tasks, spec, design, review, sa-review, decisions), committed with
  the branch and merged on approval. Spec/config files never fail the scope check.
- **Hooks (fail-open)**: TaskCreated, TaskCompleted, TeammateIdle → `data/logs/team-hooks.jsonl`.

## Learning changes the agent's body, not only its experience

- Every agent is a Markdown definition file in `data/agents/` (its own git repository: every change is a
  commit). The loop builds the agent's system prompt from this file.
- Learning after each task re-renders the file (new playbook version); the **study rotation** (setting
  `study_interval`, 0 = manual; or `gm study`, or the Evolution page) takes one agent at a time, reads new
  research knowledge and its lessons, and rewrites the file's *Working method* and *Knowledge notes*.
- Definitions can be read and edited on the agent card (Definition tab); edit the two learned sections
  there, mission/skills/model on the card itself.

## Security: the session cookie (asked: "Do you provide security for cookies? How?")

Yes. The cookie `ac_session` holds the session token **sealed with AES-256-GCM** (key in `data/secret.key`),
bound to the browser's User-Agent and, over plain HTTP, also to the client IP; a copied cookie does not work
elsewhere. It is `HttpOnly` (no JavaScript access), `SameSite=Lax` (not sent on cross-site posts), `Secure`
on HTTPS, and expires after 30 days. Added now: security headers on every answer (`X-Content-Type-Options`,
`X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`) and `no-store` on API answers. Over HTTP the
device secret still crosses the network in the clear (known issue C1): use HTTPS.

## Speed

Measured: the server answers in 3–12 ms (static files and API). The slowness was in the browser:
- The Workspace explorer re-listed every open folder every 8 s and on every live event (855 of the last 3000
  requests), Claude panel polls ran even when not visible, and every live event re-rendered the whole view.
- Static files were sent `no-cache`, so every page load revalidated ~15 files.
Fixed: static files now load from versioned URLs (`?v=<hash>`) cached for a year; (frontend fixes below).
Caveat that cannot be fixed server-side: a browser that has not installed the company CA (Settings →
Connection) gets a certificate warning and **Chrome then disables its cache**, so every load re-fetches
everything (known issue C2). Tabs opened before this update run the old scripts until reloaded.

## Workspace

- **Claude Code panel**: each tab keeps its own conversation view (switching tabs no longer reloads), work in
  background tabs keeps updating, and polling continues when you leave the Workspace and come back. New
  conversation opens a tab. **Codex** can be chosen per conversation (Copilot shows as not installed). The
  **Compact** button runs `/compact` on the conversation (tested: 18k → 3k tokens). "no folder open" removed.
  The attach button is right of the prompt, the round send/stop button under it. Tab close buttons always
  show; closing a working tab asks to stop it first. A new conversation's tab opens on the far left. Other
  Claude Code sessions on the host (VS Code, terminal, SDK) no longer get a tab each: they stay listed in the
  sessions window (Running and History, the full history), and one opened from there has a tab only while it
  is the selected one.
- **Terminal**: reconnect button; Enter or a click on a lost terminal reconnects; lost terminals reconnect by
  themselves when you come back to the tab; a shell the server no longer has reopens in the same folder.
- **Windows**: every Workspace window (explorer, editor, terminal, Claude Code) has minimise and maximise
  buttons (minimised side windows become a slim strip; click it to restore).
- **Explorer** (closer to VS Code): inline new file / new folder / rename in the tree, a name filter
  (filter button or Ctrl+F), git decorations (modified, added, untracked, deleted, renamed; folders with
  changes get a dot), and **"+"** splits the explorer: each new pane has its own folder (a registered root, or
  any folder from "/" through the picker) and can be closed; the first one stays. File icons are drawn like a
  VS Code icon theme (a coloured page per file type with its short name; coloured folders by name).
- **File Manager**: the Workspace's explorer, preview and terminal, without Claude Code; "+" adds panes.
