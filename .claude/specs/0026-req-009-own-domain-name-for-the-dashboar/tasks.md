## 1. Specify own domain names for the dashboard (REQ-009)
- key: `spec` · role: architect · writes: no

Write a short technical spec (at most about 1 page) for REQ-009, based on the current code. Read src/agent_company/transport.py (hosts ~166, _san ~173, _leaf_ok ~207, ensure_certs ~220, info ~255, nginx_conf ~290, apply ~375), src/agent_company/prefs.py (SCHEMA, CHOICES, set_value ~220 with its `transport` hook, clear ~316), src/agent_company/config.py (Settings, load_settings), src/agent_company/static/admin.js connectionCard and tests/test_transport.py. Fix these points:
1. Setting `tls_domains`: a str in Settings/prefs SCHEMA holding a comma- or space-separated list. Its .env fallback is TLS_DOMAINS (empty by default). It is stored normalised: lowercase, no trailing dot, de-duplicated, sorted, comma-joined.
2. Validation in transport.py as `parse_domains(text) -> list[str]`, which raises ValueError with the offending name. Each label is 1-63 chars of [a-z0-9-] and does not start or end with '-'. The whole name is at most 253 chars. The name is not an IP address and contains no wildcard, port, scheme, path or whitespace. At most 20 names. Examples: 'agent-company.internal' and 'dash.lan' are valid; 'http://x', '*.x', 'a..b', '-a.b', '1.2.3.4', 'x:443' and a 64-char label are rejected.
3. hosts() adds parse_domains(settings().tls_domains). The existing TLS_HOSTS env stays. Because _leaf_ok checks that the wanted SANs are a subset of the certificate's, a new name triggers renewal. A removed name does not need to trigger renewal; say this explicitly.
4. nginx_conf(mode) renders `server_name _ <names...>;`. `_` stays, so the site still answers for IP addresses and for localhost.
5. prefs.set_value/clear for `tls_domains`: validate first (ValueError → 400, setting unchanged). Then transport.ensure_certs() and transport.apply(settings().transport, force_reload=True), with the same failure semantics as `transport`. Nothing touches nginx unless MANAGE_NGINX is on.
6. /api/tls info() exposes `domains`. The API uses the existing PUT/DELETE /api/settings/tls_domains, which is already audited.
7. UI: a Domain names field in the Connection card with Save/Reset, showing the certificate hosts afterwards.
8. ReadMe.mdx: client setup via DNS records or a hosts-file line (Linux/macOS /etc/hosts, Windows C:\Windows\System32\drivers\etc\hosts), and that the CA must be trusted. This is documented, not automated.
9. Test list: parse_domains valid/invalid cases; a certificate's DNS SANs include a configured name and still include 127.0.0.1; changing the names renews the certificate; nginx_conf text contains `server_name _ agent-company.internal;`; the setting is rejected via prefs.set_value with a bad name. Tests use a tmp DATA_DIR and MANAGE_NGINX off and never call systemctl/nginx.
End with the list of files each implementation task may change.
