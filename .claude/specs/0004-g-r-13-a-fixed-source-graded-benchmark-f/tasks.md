## 1. Specify the G-R-13 research benchmark: suite format, runner, grading, isolation
- key: `spec` · role: architect · writes: yes

Write .claude/specs/g-r-13-research-benchmark/spec.md. Create the directory: in K1 a spec task failed because its spec file did not exist, so make sure the file is actually written. Read src/agent_company/evaluation.py (run_suite, summary, dimensions, compare, the EvalRun usage), src/agent_company/research.py (run_report lines ~1294-1380, REPORT_INSTRUCTIONS, _section, _excerpt, check_claims, search, injection_flags), src/agent_company/learning.py retrieval, db.py EvalRun, and G-R-13 in docs/requirements/guides-and-other-sources.md. The spec must define:
(a) The evals/research.json format. Top level: kind 'research', name, version, skills ['research'], and `documents` [{n, url 'eval-research://research/<n>', title, text, optional reliability: 'reliable'|'unreliable'|'injected'}]. Each task has name, title, category (find|verify|summarise|compare|tests|recommend), question, documents [n...], and expect {cite: [urls], contains: [quotes/facts, case- and whitespace-insensitive], forbidden: [phrases a finding must not assert], sections: ['Findings','Sources',...] taken from REPORT_INSTRUCTIONS}. Give a minimum support share (e.g. min_supported 1.0 by default, overridable per task). Note how the format grows to 100 tasks: tasks only reference documents by n.
(b) The runner evaluation.run_research_suite(data, label, repeats, only, budget_usd), dispatched from run_suite when kind == 'research'. It must honour the budget stop exactly as run_suite does. Per task and repeat it uses registry.staff('research', ['research']) and releases the agent in a finally block, and it builds the material in the same `[i] <document url=... kind=... title=...>` format. It sends executors.Request(purpose='report', role='research', prompt with the same REPORT_INSTRUCTIONS) through router.resolve('research', agent.model_pref) and executors.for_choice, and records usage.record(..., purpose='eval'). It never calls review_report, conclude, _transfer or _proposals, never creates a ResearchReport row, and never writes a Lesson.
(c) Grading without a model judge, using research.check_claims. Recommended isolation design (see the decision): check_claims gets an optional `documents` argument, a mapping n → in-memory Document-like object that is never added to the session. With that argument check_claims makes no DB lookup, and its behaviour for existing callers is unchanged. Dimensions: citation (supported/total findings), completeness (required URLs cited in the Sources section or as [n] citations, required facts present), forbidden (forbidden claims found in the findings), sections (missing sections), plus the existing efficiency keys (cost, seconds, tokens). A run passes only if every criterion passes. EvalRun: goal_id None, status 'passed'|'failed'|'error', end_reason naming the first failed criterion, iterations 1, and score = the share of criteria passed.
(d) Isolation guarantees and how the tests prove them. No row in documents, knowledge_items, blackboard, proposals or research_reports. eval-research:// URLs are refused by crawl/collect.
(e) The CLI: `eval --suite research --label X` resolves evals/research.json.
(f) The test list from the goal, item 5.
Write in English and keep it concise.
