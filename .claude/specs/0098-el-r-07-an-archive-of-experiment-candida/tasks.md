The spec must define:
1. Data model. New nullable columns on Experiment: `parent_id` (int, indexed: the experiment this candidate started from) and `eval_log` (a JSON list of entries such as {at, event, side, label, runs, pass_rate, solved_tasks, regressions, note} appended at each stage: proposed, baseline, candidate, comparison, competition result, review/apply/reject). Also a way to group competing candidates (for example a `competition` id, or `dataset['competition']`). Name the migration path through _add_missing_columns.
2. Recording. record()/propose() accept `parent_id`. A parent must exist and have the same target (and the same role or agent where the target has one), otherwise ValueError. update() appends to eval_log whenever results change. to_dict exposes parent_id, eval_log and the lineage chain (ancestor ids, root first) through a `lineage(exp_id)` function.
3. Choosing a parent (archive sampling). `pick_parent(target, role|agent_id, mode='best'|'diverse')` takes the archive of finished experiments for that target. 'best' returns the one with the highest candidate pass_rate whose comparison has no regressions; ties go to lower cost_per_passed, then to the lower id. 'diverse' returns a deterministic choice: the archived candidate whose solved_tasks set differs most (Jaccard distance) from the best one's, excluding the best itself. Say what happens when the archive is empty (None) and how a new candidate is proposed from a parent, starting from the parent's candidate payload.
4. Competition. `compete(exp_ids)` (or propose_many) runs 2 to 3 candidates against one shared baseline on the same suite and repeats. More than 3, different targets/suites/repeats, or fewer than 2 raise ValueError. The baseline is measured once and reused for every candidate's compare(). Selection: only candidates with comparison.better == True (which already excludes regressions, G-R-11) are eligible. The best is the one with the highest pass_rate, then the lowest cost_per_passed, then the lowest id. Only the winner moves to status 'review' (proposed). The others go to 'rejected', with a decision naming the winner, and each loser's eval_log records why. With no eligible candidate, all are rejected. Keep the existing per-target apply/canary paths unchanged. Name a pure selection function (for example `select_best(comparisons)`) so that tests can check it without running evals.
5. Budget: the competition's total budget is the sum of its candidates' budgets and stops all of them as _stopped does today. State this or document a simpler rule.
6. Test plan for tests/test_experiment_archive.py: (a) lineage is stored: a child proposed with parent_id has parent_id and eval_log persisted, and lineage() returns [root, child]; a parent of another target raises; (b) three competing candidates, with fake eval sides (monkeypatch the side runner the way existing tests do), where candidate A has the highest pass rate but a regression, B is best without regressions, and C is worse. Only B ends in 'review' (proposed); A and C are 'rejected'. (c) More than three candidates raise ValueError. (d) pick_parent best and diverse on a small archive.
Give exact function signatures, status transitions and audit/log_event lines. Do not write code. If any part of the requirement is ambiguous, list it under 'Open questions' with your chosen default.
