---
name: test-driven-development
description: Write the failing test first, then the code that passes it.
---

1. A test that states the wanted behaviour and fails for the right reason.
2. The smallest change that passes.
3. Refactor with the tests green.
- Cover the edge cases the acceptance conditions name; a bug fix starts with a test that fails without the fix.
- Never weaken or delete a test to pass.
